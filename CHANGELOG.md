# Changelog

## Unreleased
- Add `floom-plugin-package-info` (from `docs/plugin-catalog.md`, batch 1 / A4): the running app's own identity — name, bundle id, version, build number — read from `PackageManager` on Android and `NSBundle` on iOS **and macOS**. Unlike the nine mobile-only plugins, its Apple arm compiles under an ordinary host `cargo test`, so part of the native code is exercised by the host gate. Fields are `Option<String>` for the reason battery's `level` is: Linux and Windows have no answer today, and `Some("")` would be a value nobody measured. Registered in all eight places the catalog lists (workspace members, default-members, gate clippy + plugin lists, architecture gate, layer table, CI android/ios checks), and wired into the `floom-capabilities` gallery, whose module doc had recorded `app_info` as a dropped row waiting for exactly this crate. The gallery reports the macOS bare-binary case as `Error` — "the platform has it, this invocation cannot serve it" — rather than `Absent`, which would claim macOS lacks the capability.
- Import the satellite projects into this repository under `crates/ecosystem/`: `floom-ui` (the Material / Cupertino / Fluent kit, previously the misspelled sibling repo `flome-ui`, imported with its 17-commit history via `git subtree`), `floom-editor`, and `flameo`. Each stays its own nested workspace and is excluded from the root, so `cargo test --workspace` is unchanged; `examples/{custom_keymap,widget-gallery}` are repointed at the in-repo editor. See `docs/ecosystem.md`.
- Rename the vendored OHOS backend off the `tgui` namespace: `crates/vendor/tgui-winit-ohos` → `crates/vendor/floom-winit-ohos` (`tgui-winit-ohos` → `floom-winit-ohos`, `tgui_winit_ohos` → `floom_winit_ohos`). Because a `[patch.crates-io]` entry must keep the name of the package it replaces, the fork becomes a plain path dependency in `[workspace.dependencies]`. The rename also **fixes a latent OHOS-only bug**: the fork pinned `floem-winit-core` / `dpi` to the git rev while the patched `floem-winit` facade used the vendored copies, so the resolve graph held two `floem-winit-core` and three `dpi` instances and the backend required a different `ApplicationHandler` than the one `floom::Application` implements. `[patch."https://github.com/lapce/winit"]` now pins every member of the fork.
- Reorganise the workspace after the [EpicGames/lore](https://github.com/EpicGames/lore) model. The legacy v1 crates move under `legacy/` with a `floom-legacy-` prefix (`floom_renderer` → `floom-legacy-renderer`, `floom_reactive` → `floom-legacy-reactive`, `floom-test` → `floom-legacy-test`, plus the four renderer backends), vendored third-party forks move to `crates/vendor/` with a per-fork `NOTICE.md`, and `notices/` is added for license compliance. See `docs/workspace-conventions.md`.
- Use by default `std::sync::mpsc::channel` and place crossbeam behind the `crossbeam` feature [#775](https://github.com/lapce/floom/pull/775)
