### 修复：Batch 18 demo 段 4× E0277（重要）
首次全量 `cargo check --workspace` 被误报 0 错误——实为后台 cargo 仍在编译、demo 报错未 flush
时被 `grep '^error'` 提前读到（timing artifact）。真实情况：`floom-demo` 始终无法编译，4 个
错误全在 Batch 18 Transitions demo 段：`E0277 expected a Fn() closure, found dyn View`。

根因：Transition 组件 `child<F, IV>(child: F) where F: Fn() -> IV + 'static` 要求**闭包工厂**
（子视图须在每次 enter/leave 挂载时重建，`AnyView` 不可 Clone）；而 Batch 18 demo 照搬了
`Overlay::child`（接受 `impl IntoView` 值）的写法，传了 `value.into_any()`。修复：4 处改为
`.child(|| { view })` 并去掉内层 `.into_any()`（examples/demo/src/main.rs，仅 demo 段）。

## Demo 重构：双栏主从 + dialog 点击修复

续上一轮 Batch 20 收尾。新需求：① 已实现 NumberInput/PullToRefresh/ConfirmEdit（无需重做）；
② demo 改为「左 98 组件名列表 + 右属性变体」双栏主从；③ 修复 dialog 点击无响应。

### 方案
- 新建 `examples/demo/src/gallery.rs`：`build() -> Gallery { pages: Vec<(String, Page)>,
  overlays: Vec<AnyView> }`，`Page = Box<dyn Fn() -> AnyView>`。98 个组件各一页（按 canonical
  顺序），每个 page 工厂用 `page(title, content)` 包标题；复用原 main.rs 各段片段。
- 重写 `examples/demo/src/main.rs`：左 `Scroll`+`v_stack_from_iter` 组件名按钮（点击设
  `selected` 信号、active 行 reactive 高亮），右 `Scroll`+`dyn_view` 渲染 `pages[selected].1()`。
- **Form / PullToRefresh 页**：用 `SharedView`（`Rc<RefCell<Box<dyn View>>>` 手动 delegate
  `View`，实现 `Clone`）承载一次性建好的视图；其 `create_effect`（Form 校验 / PTR 完成）在
  `build()` 内建一次，避免每次切换页面重建视图或泄漏 effect。

### Dialog 根因与修复（需求③）
原 demo 把 `Dialog::view()` 等浮层 `push` 进可滚动 `list`，浮层 scrim 的
`width_pct(100%).height_pct(100%)` 在弹性列表项内塌缩为 0 高 → 不可见/不可点。修复：把 6 个
浮层（Dialog/Menu/Snackbar/NavigationDrawer/Sheet/Overlay）的 `view()` 单独收集，在 `main.rs`
以 `absolute().inset_top(0).inset_left(0).width_full().height_full()` 容器作为**窗口根**全屏
子节点渲染（scrim 因此铺满全窗口）；各浮层页只放触发按钮 + 说明。
