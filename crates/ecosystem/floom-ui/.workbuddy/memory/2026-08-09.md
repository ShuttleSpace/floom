# 2026-08-09

## Material design-system components: `view()` implemented for all 10

Implemented `view()` (renderable + interactive) for all 10 Material crates:
`md-button`, `md-text`, `md-text-field`, `md-checkbox`, `md-switch`,
`md-dialog`, `md-menu`, `md-card`, `md-icon`, `md-divider`.

Pattern (per component): constructor builds props + `theme_signal()`, `view()`
composes Floom primitives (`Button`, `Container`, `text`, `svg`, `TextInput`,
`Overlay`, `v_stack`/`h_stack`) and styles them from token-first theme
(`theme.component(ComponentId::X)` → `ComponentTokens::X(tokens)`).

### Key API facts verified against Floom source (git pin 778bb5f)
- `RwSignal` is `!Sync` → global theme uses `thread_local! + OnceCell`, NOT `static/OnceLock`.
- `set_disabled(bool)` is a Style method (deprecated `.disabled()` on Decorators replaced).
- `width_pct/height_pct(f64)`, `padding_horiz/vert`, `max_width(f32)`, `min_width`, `apply_if(bool, f)`.
- `Overlay::new(child)` (static) and `Overlay::new_dyn(fn)` (dyn).
- `TextInput::new(RwSignal<String>)` + `.placeholder(&str)` + `.on_enter()`.
- Focus: `listener::FocusGained` / `FocusLost` via `.on_event`.
- Click/key: `listener::Click`, `listener::KeyDown` (closure returns `EventPropagation::Stop|Continue`); `Key`/`KeyboardEvent` from prelude.
- `AnyView` + `.into_any()` (need `use floom::IntoView;`); `Box<dyn IntoView>` does NOT implement `IntoView` → use `AnyView` for stored children (fixed `md-card`).
- `create_effect(move |_| {..})` must run inside app reactive scope (call `view()` inside the window closure, not `main`).
- `box_shadow_blur/_spread/_color/_h_offset/_v_offset`.

### Demo
`examples/demo/src/main.rs` (`floom-demo`) rewritten to actually launch a

## Architecture insight for Cupertino / Fluent (Task #4)
`CupertinoTheme`/`FluentTheme` reuse the SAME `MaterialComponentTokens` struct
and `ComponentTokens` enum; they only differ by `MaterialComponentTokens::cupertino()`
/ `::fluent()` factory values. So per-design-system `view()` follows the
IDENTICAL token-extraction pattern as Material — the only difference is the
visual styling (rounded rects / SF-ish for Cupertino, accent fills for Fluent).
No new token structs needed.

## Compile-error fixes applied (Material `view()` + demo) — REUSABLE for Cupertino/Fluent

Got the whole Material set + `floom-demo` to `cargo check`/`build` clean. Key fixes:

- `NamedKey::Space` does NOT exist (keyboard-types 0.8.3; spec says use
  `Key::Character(" ".to_string())`). `Key::Named(NamedKey::Enter)` is valid.
- Import locations in Floom 0.2.0 (git 778bb5f):
  - `EventPropagation` → `floom::event::EventPropagation` (NOT prelude, NOT `floom::views`).
  - `listener` → prelude (`floom::prelude::*`).
  - `View`, `AnyView`, `IntoView` → crate root (`floom::view::AnyView`, `floom::IntoView`),
    NOT in prelude. So in crates that only `use floom::prelude::*` you must ALSO add
    `use floom::view::AnyView;` + `use floom::IntoView;` when using `AnyView`/`.into_any()`.
  - `Container`, `Decorators`, `text`, `label`, `h_stack`, `v_stack`, `list`, `empty`,
    `TextInput`, `Overlay`, `Button` are in `floom::views` (→ prelude via `views::*`).
- `on_event` closures (signature `FnMut(&mut EventCx, &L::EventData) -> EventPropagation + 'static`)
  MUST be passed inline; binding them to a `let` triggers
  "implementation of `FnMut` is not general enough" (HRTB) error.
- Reactive text: `label(move || <expr returning Display>)` NOT `text(move || …())`.
  `text()` takes a `Display` value (not a closure); `text(closure())` mis-parses.
- Avoid naming a local `text`/`label` — it shadows floom's `text()`/`label()` functions
  (E0618 "expected function, found String").
- Inside an `FnMut` `on_event` closure, don't `if let Some(cb) = on_select { cb(); }`
  (moves out of captured var → E0507). Use `if let Some(cb) = &on_select { cb(); }`.
- `TextStyle` is not `Copy` → clone it: `let ts = t.typography().body.medium.clone();`.
- Demo crate must depend on `floom` AND `floom-core-theme` directly (not just
  `floom-elements`/`floom-widget-runtime`), and `use floom_core_theme::theme::Theme;`
  must be in scope to call `theme.colors()`/`.typography()`/`.shadow()`.

## Cupertino `view()` pattern started (Task #4)
Implemented `CupertinoButton::view()` (compiles clean with `-p floom-widget-cupertino-button`).
Pattern confirmed: Cupertino/Fluent crates mirror Material's `view()` verbatim, swap
`MaterialTheme`→`CupertinoTheme`/`FluentTheme`, and adjust visual styling. Token
extraction (`theme.component(ComponentId::X)` → `ComponentTokens::X`) is identical.
Note: Cupertino components currently use their own `RwSignal::new(CupertinoTheme::new())`
(self.theme), NOT the global `theme_signal()` (which is `RwSignal<MaterialTheme>`).
Global cross-design-system theming is a separate concern; per-component `self.theme`
works fine for now. Helper fns (`base_colors`) are per-design-system.
